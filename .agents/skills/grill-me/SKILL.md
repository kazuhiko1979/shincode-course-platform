# Grill Me

## 目的

実装を急がず、ユーザーとの短い質疑で仕様を具体化する。ユーザーが明示的に依頼した場合、または要件の不確実性が高く事前確認が有益な場合に使う。

## 手順

1. 依頼内容を一文で仮要約し、確認が必要な論点を内部で優先順位付けする。
2. 最も影響の大きい未確定事項を1つだけ質問する。複数の質問を一度に投げない。
3. 回答を受けたら、回答を反映した仮要約を示し、次の未確定事項を1つ質問する。
4. 目的、対象範囲、対象外、制約、受け入れ条件、検証方法が確定するまで実装・ファイル編集・外部書き込みを開始しない。
5. 確定後、次の合意サマリーを提示して確認を得る。

```text
目的:
対象範囲:
対象外:
制約・前提:
受け入れ条件:
検証方法:
未解決事項: なし
```

6. ユーザーが「実装して」「進めて」など明確に開始を指示した後に、通常の `AGENTS.md`、Rules、Hooks、検証手順に従って実装する。

## 質問の優先順位

- 期待する成果と、成功・失敗を判定する条件
- 影響範囲、対象ユーザー、権限、データ境界
- 既存仕様との互換性、対象外にする範囲
- エラー時・空データ時・権限不足時の挙動
- 検証環境、テスト、リリース条件

質問は具体的な選択肢や例を添えて回答しやすくする。ただし、ユーザーの回答を誘導するために勝手な仕様を確定しない。

## 停止条件と安全規則

- ユーザーが回答を保留した論点は「未解決事項」として残し、実装を開始しない。
- DB/RLS、認証認可、依存関係、ハーネス強制系などの変更は、通常の規約どおり別途明示承認とチケットを要求する。
- ユーザーが質問フェーズを明示的に解除した場合でも、未解決のリスクと仮定を先に提示し、承認された範囲だけ進める。
- `grill-me` はレビュー担当ではない。実装後は必要に応じて reviewer、`npm run verify`、doctor を実行する。

## 出力形式

質問中は簡潔に「確認 1/複数」の形式で1問ずつ尋ねる。合意後は上記サマリーを出し、実装へ移る前に未解決事項がないことを明示する。
