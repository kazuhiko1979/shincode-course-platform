# Evaluation Rubric — フロントエンド UI 評価基準

> **目的**：Generator-Evaluator パターンの評価基準（グレーダブル・クライテリア）。
> 生成した本人の「よくできています」は構造的に信用できない（自己評価バイアス）。UI を作った後は、**別のエージェント／別セッション／人間**がこの rubric で独立採点する。
> 曖昧な「いい感じにして」を、採点可能な「低スコア／高スコアの具体状態」に固定するのがこのファイルの役割（`docs/harness/01_principles.md` §5）。

## 使い方

- **いつ**：UI の新規作成・リデザイン・デザイン調整のタスク完了前。
- **誰が**：Generator とは別の評価者（サブエージェント／別セッションの Claude／Codex／人間）。
- **どう**：`npm run dev` で**実際に操作して**評価する（コードだけ読んで褒めない）。ライト/ダーク両方・主要ブレークポイント・各ステートを確認し、軸ごとに 1〜5 で採点 → 重み付け合計 → 判定。
- 指摘は**重要度順**に、該当箇所（画面・`file:line`）と修正案を添える。

## 評価軸（6軸・重み付き）

各軸 1〜5 点。**1点/3点/5点の具体状態**に照らして採点する（中間は補間）。

### 1. 一貫性・デザインシステム（重み 25%）

| 点 | 具体状態 |
|---|---|
| 1 | 画面ごとに色・余白・角丸・フォントサイズがバラバラ。HEX 直書きが散在し、同じ役割に違う見た目 |
| 3 | 主要コンポーネントは揃っているが、一部に場当たりな余白・独自色が混入 |
| 5 | 色・余白・角丸・タイポがトークン／定数化されたクラスで統一。既存画面と並べても同一プロダクトに見える。Material 化画面は M3 トークン（`bg-primary`/`on-*` ペア等）を厳守 |

### 2. 視覚ヒエラルキー・情報設計（重み 20%）

| 点 | 具体状態 |
|---|---|
| 1 | 何が主役か分からない。見出し・本文・補足が同じ強さ。視線の流れが定まらない |
| 3 | 主役は分かるが、強弱が甘い箇所や、詰め込みすぎのセクションがある |
| 5 | 最重要要素が一目で分かる。サイズ・太さ・色・余白で階層が明確。1画面1目的に整理されている |

### 3. 機能性・UX 動線（重み 20%）

| 点 | 具体状態 |
|---|---|
| 1 | 目的のタスク（受講登録・視聴・検索など）を完了する動線が不明瞭。押せるものが押せそうに見えない |
| 3 | 動線は通るが、hover/focus/押下・loading・empty・error のいずれかのステートが未処理 |
| 5 | タスク完了までの動線が明確。インタラクティブ要素は見た目で分かり、**全ステート**（hover/focus/押下/loading/empty/error）が設計されている |

### 4. アクセシビリティ（重み 15%）

| 点 | 具体状態 |
|---|---|
| 1 | コントラスト不足で読めない箇所がある。画像 `alt`・アイコンボタン `aria-label` 欠落。キーボードで操作不能 |
| 3 | 基本は満たすが、フォーカスリングが見えない・タッチターゲットが小さい（48px 未満）箇所が残る |
| 5 | コントラスト十分（本文 4.5:1 目安）、`alt`/`aria-label` 完備、キーボードのみで全操作可、フォーカス可視、タッチターゲット 48px 以上 |

### 5. レスポンシブ・技術品質（重み 10%）

| 点 | 具体状態 |
|---|---|
| 1 | モバイルでレイアウト崩れ・横スクロール発生。画像が歪む/巨大 |
| 3 | 主要幅では崩れないが、中間幅で詰まり・折返し不良がある |
| 5 | モバイル〜デスクトップで破綻なし。ライト/ダーク両テーマで欠けなし。`next/image` の適切なサイズ指定 |

### 6. 独自性・仕上げ（重み 10%）

| 点 | 具体状態 |
|---|---|
| 1 | テンプレートのデフォルトそのまま。プレースホルダー文言・ダミー余白が残る |
| 3 | 整ってはいるが、どのサイトにもある無難な見た目に留まる |
| 5 | このプロダクトのための意図的なデザイン判断が見える。細部（数字の桁揃え・空状態の文言・角の処理）まで調整済み |

## 判定

- **総合スコア** = Σ(軸スコア × 重み) × 20（100点満点換算）
- **合格ライン：80点以上**、かつ **Critical 違反ゼロ**

### Critical（1つでも該当したら点数に関わらず不合格）

- コントラスト不足・キーボード操作不能など、利用を妨げるアクセシビリティ重大違反
- 主要ブレークポイントでのレイアウト崩れ・機能しないインタラクション
- 規約違反：`<img>`（`next/image` 不使用）・`<a href>`（`<Link>` 不使用）・インライン `style={}`

### 反復の目安（`01_principles.md` §5）

- フロントエンド UI は **5〜15回の反復**が効果的。最初の 2〜3 回で最大の改善が起きる（収穫逓減）。
- **停止基準**：合格達成 ／ 3回連続で改善なし ／ 改善幅 < コスト。完璧ではなく「基準を満たす最小限の反復」で止める。

## 採点キャリブレーション（アンカー例）

スコアのブレ（ドリフト）を防ぐため、以下を基準点として参照する。

| 例 | スコア | 判定理由 |
|---|---|---|
| 良い例：コース一覧がカードのトークン統一・空検索時の案内文・全ステート実装・ダーク対応済み | 5 | 一貫性／ステート網羅／両テーマの3要素を満たす |
| 普通の例：機能するが hover のみで focus 不可視、モバイルの余白が場当たり | 3 | 動くが、ステート欠落と一貫性の綻びで改善余地 |
| 悪い例：HEX 直書き混在・alt 欠落・モバイルで横スクロール・押せる要素が判別不能 | 1 | 一貫性・a11y・レスポンシブに重大な問題 |

## 評価レポートの形式

```
## 総合: NN/100 — 合格 / 不合格（Critical: あり/なし）
| 軸 | 点 | 根拠（画面箇所 / file:line） |
|---|---|---|
| 一貫性 | n/5 | … |
（6軸）
## 重要度順の指摘（修正案付き）
1. [Critical/High/Med/Low] 内容 → 修正案
## 良い点（維持すべきパターン）
```
