`.claude/` ハーネス・ドキュメント・ルート直下の運用ファイル（`claude-progress.txt` / `feature_list.json`）のみの差分は、**本番バンドル・リクエスト処理に一切影響しない**（`tsconfig.json` の include は `**/*.ts(x)/mts` のみで root の .json/.txt を型チェック対象にせず、アプリコードからの import も無い）。この種の差分で見るべき唯一の「性能」軸は **セッションあたりのコンテキスト消費**。

実測ベースライン（2026-08-02 / commit 93a869a 時点）:

- 常時ロード（CLAUDE.md + AGENTS.md）: 約 **15.9k 文字 / 29.3KB**（うち CLAUDE.md 9,964 文字）。日本語主体のため概算 **13〜20k tokens**。
- SessionStart 注入（`.claude/hooks/session-start.sh` の stdout）: 33 行 / 1,551 文字（progress 25 行＋固定手順）→ 概算 **1.2〜2.3k tokens／セッション**。実行コストは wall 0.00s・maxRSS 3.3MB（3回計測）で無視可能。stdout を文脈へ入れる仕組みのため同期実行が必須（async 化不可）。
- 常時ロード分はサブエージェントごとに複製される。`/push-review` は 3 並列＝メイン込み 4 文脈なので、CLAUDE.md の増加分は約 4 倍で効く。

**Why:** ハーネス整備が続く限り差分の大半は非ランタイムになり、「バンドル影響なし → PASS」で終わると唯一の実コストであるコンテキスト予算を誰も見なくなるため。相対比較の基準がないと「少し増えただけ」の判断ができない。
**How to apply:** 非ランタイム差分のレビューでは (1) ランタイム/バンドル無影響を名前ベースで確認し、(2) 常時ロード（CLAUDE.md/AGENTS.md）と毎セッション注入の増分を上記ベースラインとの比率で示す。要約＋リンクで詳細を外出ししていれば Select 戦略と整合として可とする。実行時間（フックの wall 時間）は既に無視可能と判明しているので再計測・再指摘しない（[[hook-overhead]]）。注入系スクリプトは「注入上限値」と「ドキュメント上の行数ルール」が一致しているか、および上限超過時に切り捨てられるのがファイルのどの部分かを毎回確認する。
