# ハーネス設計 1枚まとめ（チーム共有用）

> 詳細は [01_principles.md](./01_principles.md)、現状評価は [02_maturity.md](./02_maturity.md)。

## 🧭 設計哲学（これだけは覚える）

> **AI の凹みに構造を、でっぱりは安心して任せられるように。**
> **モデルが進化しても、設計したハーネス構造は資産として永続する。**

- **凹み（AIの苦手）** = 長時間の一貫性・自己評価・曖昧な要件解釈 → **構造で足場を組む**（ルール／フック／進捗ファイル／独立した評価者）。
- **でっぱり（AIの得意）** = コード生成・大量ファイル理解・定型処理 → **境界と検証だけ固めて委任する**。
- ハーネス＝「モデルが単体でできないこと」への仮説の集積。原則（W/S/C/I）はモデル非依存の**メタスキル**。

## 4つのコンテキスト戦略（W・S・C・I）

| 戦略 | ひとことで | 本プロジェクトの実物 |
|---|---|---|
| **Write** | 知識を外部ファイルに永続化 | `AGENTS.md`・`docs/`・`.serena/memories`（Claude/Codex 共通） |
| **Select** | 必要な時に必要な分だけ | `.agents/rules/*`・`.agents/skills/*`・MCP |
| **Compress** | 重要判断は残し冗長は捨てる | ハーネス自動＋全リセット運用 |
| **Isolate** | サブエージェントで分離・並列 | 3 reviewers＋`/push-review` |

## 6つの制御インターフェース

`CLAUDE.md`(常時) / `Rules`(パターン連動) / `Hooks`(実行制御) / `Skills`(明示呼び出し) / `サブエージェント`(委任) / `MCP`(外部連携)

## 品質を上げる3つの型

1. **決定論的ガードレール**：失敗が許されない操作は CLAUDE.md の「お願い」でなく **Hooks の `exit 2`** で強制ブロック。
2. **生成と評価の分離**：自己評価は信用しない。**別の評価者**（reviewers）で採点。基準は `rubric` に固定。
3. **検証ループ**：生成→検証→改善→再検証。まず**ルールベース**（`npm run verify`＋CI）、必要なら**ビジュアル**（Playwright）、**LLM-as-Judge** を足す。

## 判断の物差し

- **シンプルから始め、実測で効果が出た時だけ複雑さを足す。**
- ツールは **3〜5個に絞る**（多いほど誤選択が増える）。
- 完璧でなく、**品質基準を満たす最小限の反復**で止める（最初の2〜3回で最大改善）。
- **少コストで壊れたもの**より **適正コストで動くもの**。

## 本プロジェクトの現在地（25.5/30・85%）

- **強い**：Write戦略・Isolate＋投票レビュー・ルールベース検証ゲート・**Hooks 一式（docs/018・019）**・**Generator-Evaluator の形式化（specs/）**・**マルチエージェント運用ルーティング（05_multiagent-playbook）**・**構造化ハンドオフ（claude-progress.txt＋feature_list.json＋SessionStart フック、docs/021）**。
- **伸びしろ（凹み対策）**：①各形式化の運用実績づくり（evals の pass@k 比較・contract 検収・rubric 採点の実運転）②G-4 ビジュアル検証。
- **次の一手**：evals/tasks.json の user-request タスクを1つ選び、「contract 合意→実装→検収→pass@k 記録」を通しで実運転する（運用実績の初回）。
- **CLI 運用**：`.agents/` を Hook/Rules/Skills の正典にし、Claude Code と Codex CLI が同じ安全境界・知識を参照する。会話は `docs/`・Git diff・`claude-progress.txt` で引き継ぐ（[08_dual-cli-playbook](./08_dual-cli-playbook.md)）。

## 今日から

1. `CLAUDE.md` を育てる（追記・不要削除を続ける）。
2. 生成後は**別セッション/別エージェントで評価**して自己評価との差を体感する。
3. 「AIがXを自力でできないはず」と**仮説→補助を入れて検証**。正しければ組み込み、違えば取り除く。
